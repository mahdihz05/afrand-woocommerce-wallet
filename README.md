# دموی کیف پول و کش‌بک افرند

پنل فارسی برای پیدا کردن یا ساخت مشتری و واریز کش‌بک خرید به **کیف پول مشتری فراز اس‌ام‌اس در وردپرس**، به‌صورت تکی یا از فایل اکسل.

راهنمای نصب و دریافت بستهٔ افزونه: [نصب و تحویل فراز](INSTALL_FARAZ.md). آخرین نتیجهٔ آزمون‌ها: [گزارش پذیرش](FARAZ_ACCEPTANCE_20261103.md).

راهنمای شاخهٔ جدید و شواهد آزمون اتصال فراز: [انتقال به فراز](FARAZ_MIGRATION.md). گزارش‌های قبلی زیر مربوط به اتصال تراولت هستند.

وضعیت اتصال سایت جدید و آزمون واقعی ۲۰۲۶-۱۱-۰۱ در [گزارش تحویل آزمایشی](ACADEMY_ACCEPTANCE.md) ثبت شده است. [نقطهٔ ادامهٔ قبلی](RESUME.md) مربوط به ۲۰۲۶-۱۰-۲۸ است.

این مخزن، نسخهٔ دموی موجود را برای بازبینی و ادامهٔ توسعه نگهداری می‌کند. آماده‌بودن برای استفادهٔ عملیاتی و تحویل نهایی هنوز تأیید نشده است. ثبت محصول و سفارش مربوط به نسخهٔ قدیمی است و در حالت فعلی کیف پول غیرفعال است.

آخرین [ارزیابی امنیت، کارایی و آمادگی تحویل — ۲ نوامبر ۲۰۲۶](DELIVERY_READINESS_20261102.md): اصلاحات منتشر شده و تست‌ها موفق‌اند؛ تحویل عملیاتی به شروط باقی‌ماندهٔ همان گزارش وابسته است.

## امکانات

- جست‌وجو و ساخت مشتری با موبایل ایرانی و بدون ایمیل؛ موبایل موجود به همان حساب متصل می‌شود.
- نمایش موجودی و ۳۰ تراکنش اخیر از کیف پول اصلی وردپرس.
- محاسبهٔ کش‌بک در سرور با پیش‌فرض ۵٪ و درصد قابل تنظیم؛ خرید ۱۰۰٬۰۰۰ تومان با ۵٪، معادل ۵٬۰۰۰ تومان واریز است.
- ورود اکسل با تشخیص یا انتخاب ستون‌ها، پیش‌نمایش، خطاهای هر ردیف، تأیید و گزارش نتیجه.
- در کش‌بک اکسل، شماره سند ستون پنجم و اجباری است؛ برای هر خرید شمارهٔ یکتا بنویسید. سند قبلی از واریز تکراری جلوگیری می‌کند. مبلغ ثابت شماره سند لازم ندارد؛ بارگذاری و تأیید جدید نوبت تازه است. جزئیات در [راهنمای ورود اکسل](EXCEL_IMPORT.md).
- ورود به پنل، تأیید عملیات، نمایش بارگذاری و رابط راست‌به‌چپ مناسب موبایل.

راهنماها: [نمایش دمو](demo/README.md)، [نمونهٔ اکسل کیف پول](demo/afrand-wallet-sample.xlsx)، [سوابق بررسی](demo/verification.md)، [افزونهٔ وردپرس](wordpress/README.md)، [استقرار دمو](deploy/README.md).

## ساختار فنی

بک‌اند Python/Flask، رابط JavaScript و CSS ساده و SQLite برای پیش‌نمایش‌ها و سوابق عملیات استفاده می‌شود. موجودی و تراکنش مالی اصلی در WordPress/Faraz SMS نگهداری می‌شوند؛ SQLite کیف پول جداگانه نیست.

```text
panel/       منطق برنامه، ورود، اکسل و اتصال به WooCommerce
templates/  صفحات فارسی پنل
static/      فایل‌های رابط
wordpress/   افزونهٔ Afrand Wallet Bridge
tests/      تست‌های خودکار
demo/       نمونه‌ها و سوابق بررسی دمو
deploy/     Dockerfile و راهنمای استقرار
scripts/     ابزارهای بررسی؛ برخی مربوط به نسخهٔ قدیمی‌اند
```

## راه‌اندازی محلی

پیش‌نیازها: **Python 3.12 یا جدیدتر** و `uv`. برای اتصال واقعی، سایت آزمایشی WordPress با WooCommerce، Faraz SMS و [Afrand Faraz Wallet Bridge](wordpress/README.md) نیاز است.

```bash
git clone https://github.com/mahdihz05/afrand-woocommerce-wallet.git
cd afrand-woocommerce-wallet
git switch feature/farazsms-wallet
uv sync --frozen
```

فایل `.env.example` را به `.env` کپی کن؛ در PowerShell:

```powershell
Copy-Item .env.example .env
```

هش رمز ورود را با ورودی پنهان بساز و در `PANEL_PASSWORD_HASH` داخل `.env` قرار بده:

```bash
uv run python -c "from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass('Panel password: ')))"
```

برای `FLASK_SECRET_KEY` مقدار تصادفی حداقل ۳۲ بایتی بساز و فقط در `.env` نگهداری کن. با ورود فعال، کلید خالی، کوتاه یا تکراری پیش از شروع سرویس رد می‌شود؛ کلید عمومی دمو قابل استفاده نیست. کلیدهای چرخش نشست (`SECRET_KEY_FALLBACKS`) نیز باید همین شرایط را داشته باشند:

```bash
uv run python -c "import secrets; print(secrets.token_hex(32))"
```

| متغیر | کاربرد |
| --- | --- |
| `WC_BASE_URL` | نشانی HTTPS سایت آزمایشی خودت |
| `WC_STAGING_HOST` | نام میزبان همان سایت، بدون پروتکل یا مسیر |
| `WC_CONSUMER_KEY` / `WC_CONSUMER_SECRET` | کلیدهای WooCommerce؛ فقط سمت سرور |
| `WC_ENVIRONMENT` | برای دمو `staging` |
| `WC_WRITES_ENABLED` | پیش‌فرض `false`؛ فعال‌سازی صریح برای نوشتن روی staging |
| `WALLET_MODE` | برای جریان فعلی `true` |
| `PANEL_USERNAME` / `PANEL_PASSWORD_HASH` | حساب ورود پنل |
| `FLASK_SECRET_KEY` | کلید تصادفی نشست، اختصاصی هر محیط |

آدرس در `.env.example` سایت آزمایشی جدید `www.afrandacademy.ir` است؛ برای مقصد دیگر، آدرس و میزبان staging را با هم تغییر بده و پایگاه دادهٔ مستقل تعیین کن. کلید API به `manage_woocommerce` و برای ساخت مشتری به `create_users` نیاز دارد. رمز مدیر وردپرس در پنل استفاده نمی‌شود.

```bash
uv run python run.py
```

سپس `http://127.0.0.1:5055` را باز کن. بدون هش رمز، ورود فعال راه‌اندازی نمی‌شود؛ بدون اتصال صحیح نیز عملیات کیف پول قابل انجام نیست. تست‌های واحد به سایت یا کلید واقعی نیاز ندارند.

## قواعد فعلی دمو

- کش‌بک = مبلغ خرید × درصد ÷ ۱۰۰؛ گرد کردن رو به پایین به واحد کامل کیف پول.
- درصد بیشتر از صفر تا ۱۰۰، با حداکثر دو رقم اعشار؛ کش‌بک کمتر از یک واحد پذیرفته نمی‌شود.
- سایت جدید بر پایهٔ ریال (`IRR`) است. واحد از کیف پول مقصد خوانده می‌شود؛ تبدیل خودکار ریال/تومان وجود ندارد.
- در کش‌بک اکسل، شماره سند ستون پنجم و اجباری است؛ برای هر خرید شمارهٔ یکتا بنویسید. سند قبلی از واریز تکراری جلوگیری می‌کند. مبلغ ثابت شماره سند لازم ندارد؛ بارگذاری و تأیید جدید نوبت تازه است. جزئیات در [راهنمای ورود اکسل](EXCEL_IMPORT.md).
- فایل باید تک‌برگه‌ای، حداکثر ۲ مگابایت و ۱۰۰۰ ردیف باشد؛ فایل چندبرگه‌ای پیش از واریز رد می‌شود تا مشتریان برگه‌های دیگر جا نیفتند. حداکثر مبلغ خرید هر ردیف ۱۰۰ میلیون واحد. تطبیق موبایل‌ها دسته‌های حداکثر ۱۰۰تایی و اجرای مالی دسته‌های دوتایی دارد.
- پیش‌نمایش و نتیجهٔ ردیف‌ها روی SQLite ماندگار است؛ از «فایل‌های ذخیره‌شده» پس از بستن صفحه یا راه‌اندازی مجدد ادامه دهید. مقدار نامشخص ابتدا استعلام می‌شود؛ تغییر شماره سند راه بازیابی نیست.
- شرکت مشتری جدید به `billing_company` می‌رود؛ تغییر شرکت مشتری موجود فقط با فرم مستقل و تأیید صریح انجام می‌شود. اکسل شرکت موجود را بازنویسی نمی‌کند.
- در کش‌بک اکسل، شماره سند باید در شعب و سال‌ها هم یکتا باشد. تکرار سند نتیجهٔ قبلی را بازیابی می‌کند؛ تغییر مشتری، خرید یا درصد برای سند قبلی رد می‌شود.
- پیش‌نمایش اکسل تا پیش از تأیید چیزی نمی‌نویسد؛ ردیف نامعتبر ثبت نمی‌شود. تغییر درصد، پیش‌نمایش قبلی را باطل می‌کند.

## بررسی و تست

```bash
uv run --frozen python -m unittest discover -s tests -q
```

مرورگر با بک‌اند موقت و بدون نوشتن در سایت خارجی:

```bash
uv run --with playwright playwright install chromium
uv run --with playwright python scripts/verify_wallet.py
```

سوابق تست و پذیرش staging در [verification.md](demo/verification.md) تاریخ‌دار هستند؛ سلامت آنلاین امروز را اثبات نمی‌کنند. گزارش‌ها و تصاویر تولیدشده در `instance/verification/` محلی و خارج از Git می‌مانند.

`scripts/verify_wallet_live.py --live-staging` روی سایت تنظیم‌شده مشتری و تراکنش واقعی آزمایشی می‌سازد؛ فقط با مجوز مشخص برای همان staging اجرا شود. اسکریپت‌های قدیمی سفارش، مسیر پذیرش نسخهٔ فعلی نیستند.

## وضعیت و مسیر تکمیل

راهنمای نصب Passenger، الزامات دیتابیس و محدودیت آزمون‌ها: [DELIVERY_INSTALL.md](DELIVERY_INSTALL.md). آزمون هم‌زمانی محلی با کیف پول ساختگی: `python tests/load_wallet.py`؛ این آزمون جای پذیرش WordPress/Faraz SMS واقعی را نمی‌گیرد.

این دمو مبنای توسعهٔ نسخهٔ اصلی است. برای تحویل، تعهدات قرارداد، قواعد نهایی کش‌بک و مرجوعی، خروجی واقعی حسابداری، نقش‌ها و دسترسی‌ها، محیط نهایی و سناریوهای پذیرش باید مشخص و آزموده شوند. پشتیبانی از فایل عمومی اکسل به معنی تأیید سازگاری با نرم‌افزار حسابداری خاص نیست.

کلیدها، رمزها، دیتابیس، قراردادها و خروجی‌های موقت در این مخزن قرار نمی‌گیرند. راهنمای استقرار و گزارش‌های قدیمی سوابق دمو هستند؛ اجرای آن‌ها مجوز تغییر سرور یا استفاده از دادهٔ واقعی نیست.
